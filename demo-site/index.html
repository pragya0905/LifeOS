Write a sentence.
LifeOs fills in the rest.

A full-stack life-tracking app where a normal journal entry — not a form — is the primary way data gets in. An LLM reads what you wrote and quietly populates tasks, habits, medications, budget, and more across a serverless AWS backend.

The product

Not a mockup — a real, deployed app

Screenshots below are captured live from the running system, not designed in Figma. Same coral-on-paper design system end to end, light and dark, desktop and mobile.

Dashboard — a Prev/Next day selector drives every card on the page at once; schedule, habits, routines, and medications all switch to show that day's own data. The water/exercise/steps numbers below weren't typed in — they came from one journal sentence.

Mobile — installable PWA, reflowed layouts (not just shrunk desktop ones) on narrow viewports.

Journal — same free-text entry, but now Claude also scores the day: a productivity number, wins, and suggestions, grounded in what was actually completed that day, not just the text's tone. The "20 min felt wasted" line only appears because the entry said so — it's never inferred from silence.

Tasks — watch the top task: priority was forced to High automatically, with the reasoning shown inline, the moment the math proved the estimated effort no longer fit before the deadline. No AI call needed for that — it's deterministic.

Cycle — phase and next-period prediction estimated from your own logged history, never a medical claim. Hidden entirely from navigation if you set sex to male.

Routines — multi-step daily checklists with per-step done/skipped state and consecutive-day streaks, started from templates or built from scratch.

Engineering — LLM inference, RAG, and the serverless backend underneath

A few decisions worth asking about

Real tradeoffs made while building and operating this, not a features list.

🔐

Cross-user data leaks are structurally impossible

Every one of 19 DynamoDB tables partitions by the authenticated user's ID, resolved once from a verified JWT claim — never a client-supplied field. The key needed to reach another user's row never appears in a request built from your own auth context.

🐛

Found and fixed a real caching bug in production

A 4-second GET cache added to cut duplicate requests started bouncing new users into an onboarding loop — a stale read landing right after a write to the same resource. Fixed by clearing the whole cache on any successful write, and re-verified live before calling it done.

🧮

Doesn't trust an LLM with arithmetic

"Walked 10km" needs to become a step count, but LLMs are unreliable at multi-step math. The model reports raw distance only; the actual step count is computed deterministically from the user's stored height with a standard stride formula.

⚡

Closed an N+1 without touching the schema

Goal progress for habit-linked wishes ran one extra query per wish. Rewrote it to one combined query covering every wish's date range, with per-wish progress computed in memory — 1+N calls became a flat 2, regardless of how many goals a user has.

🎙️

A chat assistant that reuses the app, not a second copy of it

The voice/chat Assistant's tool-calling Lambda forwards every action to the same HTTP API routes the web app calls, with the same bearer token — the exact thin-adapter pattern already proven by a separate Alexa skill integration. "How a task gets created" lives in exactly one code path, no matter which surface asked for it.

🔎

RAG over your own journal, no vector database

Every journal save gets embedded (Bedrock Titan) independently of the AI extraction, so neither can block the other. Semantic search runs as brute-force cosine similarity over one user's journal partition in Lambda memory — no dedicated vector store needed at a few hundred to low-thousands of entries per person. Ask the Assistant "what have I said about my landlord" and it answers from entries that never used that word.

📐

Coaching that's honest, not just encouraging

Ask the Assistant how you're doing and it calls a tool that computes — in code, not by model guess — which goals are falling behind schedule, which habit streaks broke, and whether this month's spending is on pace to bust the budget. It's told to name the gap plainly before any encouragement, never instead of it.

🍽️

AI proposes, an explicit action commits

The weekly Meal Plan's "Suggest with AI" fills empty slots with a one-shot Claude call — but nothing is written until a separate Save. Same separation the task-priority guardrail uses: the model proposes, a deliberate action always commits. Ask the Assistant to critique the plan instead, and it can revise a slot directly mid-conversation once you agree to the change.

⚡

Real token streaming meant leaving API Gateway for one route

API Gateway's proxy integration buffers a Lambda's whole response before returning it — no way to stream through it. The Assistant's chat now runs behind its own Lambda Function URL with response streaming instead, which doesn't support the shared Cognito authorizer, so that one function verifies the JWT itself (via AWS's own aws-jwt-verify library) before committing to any HTTP status — checked with both a valid and a deliberately invalid token before calling it done, since that's the one place auth isn't the platform's problem anymore.

🧩

Inference constrained to a schema, not parsed from prose

Journal extraction, insights, task-priority, and meal-plan suggestions all call Claude through the SDK's schema-constrained output helper against a Zod schema — the response is guaranteed-shape JSON, never regex'd out of freeform text. Every field stays optional/nullable so the model leaves things unset rather than inventing a value for something the entry never mentioned.

🧪

Measured a model's reliability instead of assuming it

Wiring a newly-unlocked achievement into the Assistant's context worked immediately on Sonnet but silently didn't fire on Haiku — even after rewriting the instruction as a hard imperative. Isolated by swapping only the model with identical code and prompt: a genuine instruction-following gap between tiers, not a bug. Documented and left as a known cost/capability tradeoff rather than papered over with a forced workaround.

🧠

A memory system that can forget, not just accumulate

The Assistant can save a short durable fact about the user mid-conversation — but for months that was write-only: nothing let it correct or retract one once the context changed. Added update/forget as first-class tool calls alongside remember, so a finished goal or a wrong detail doesn't sit in every future prompt forever. Verified live: a corrected preference lands with the same memory id and a fresh timestamp; a resolved one disappears outright.

🚫

A number the model is told not to guess

Journal entries now get a productivity score and a "time felt wasted" estimate — but the app tracks no screen-time data at all, so that second number can only ever come from what the entry itself says. The system prompt is explicit: return null, never infer a figure from a busy-sounding day or from silence. Verified live with two entries on the same data — one naming a real distraction got a number back, a quiet day with nothing mentioned came back null, not a guess.

🐛

An AI write collided with data already entered by hand

Journaling about a purchase already logged manually on the Budget page quietly created a second expense row for the same thing — the AI-extraction dedup only checked its own past writes, never the user's manual ones. Fixed by matching on amount against that day's manual expenses before writing, found and reproduced against the real affected account, not a synthetic repro.

✍️

Composing a tool call from two different sources of truth

"Write today in my journal" has to blend what was actually said in the conversation with what's really logged — so that request now triggers a read (the same deterministic daily-status tool used elsewhere) before the write, and the result is upsert-safe: a second journal entry for the same day appends instead of failing a uniqueness check. Verified live: a deliberately wrong step count in chat got caught against the real logged number and corrected before anything was written.
