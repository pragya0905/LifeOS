Write a sentence.
LifeOs fills in the rest.

A full-stack life-tracking app where a normal journal entry — not a form — is the primary way data gets in. An LLM reads what you wrote and quietly populates tasks, habits, medications, budget, and more across a serverless AWS backend.

The product

Not a mockup — a real, deployed app

Screenshots below are captured live from the running system, not designed in Figma. Same coral-on-paper design system end to end, light and dark, desktop and mobile.

Dashboard — every ring, streak, and card above updates itself from that one journal sentence. Nothing here was manually entered except the journal text.

Mobile — installable PWA, reflowed layouts (not just shrunk desktop ones) on narrow viewports.

Journal — the actual input surface behind the demo above: free text, voice input, mood picker.

Tasks — watch the top task: priority was forced to High automatically, with the reasoning shown inline, the moment the math proved the estimated effort no longer fit before the deadline. No AI call needed for that — it's deterministic.

Cycle — phase and next-period prediction estimated from your own logged history, never a medical claim. Hidden entirely from navigation if you set sex to male.

Routines — multi-step daily checklists with per-step done/skipped state and consecutive-day streaks, started from templates or built from scratch.

Engineering

A few decisions worth asking about

Real tradeoffs made while building and operating this, not a features list.

🔐

Cross-user data leaks are structurally impossible

Every one of 14 DynamoDB tables partitions by the authenticated user's ID, resolved once from a verified JWT claim — never a client-supplied field. The key needed to reach another user's row never appears in a request built from your own auth context.

🐛

Found and fixed a real caching bug in production

A 4-second GET cache added to cut duplicate requests started bouncing new users into an onboarding loop — a stale read landing right after a write to the same resource. Fixed by clearing the whole cache on any successful write, and re-verified live before calling it done.

🧮

Doesn't trust an LLM with arithmetic

"Walked 10km" needs to become a step count, but LLMs are unreliable at multi-step math. The model reports raw distance only; the actual step count is computed deterministically from the user's stored height with a standard stride formula.

⚡

Closed an N+1 without touching the schema

Goal progress for habit-linked wishes ran one extra query per wish. Rewrote it to one combined query covering every wish's date range, with per-wish progress computed in memory — 1+N calls became a flat 2, regardless of how many goals a user has.
